## Calls under runbook section 3 (disclosed in the report)

1. Parity matrix ("each theme ... each accent", "sidebar open and closed"): every brief in flat light, sculpted light,
   flat dark, sculpted dark, tinted and flat light Recall, desk and phone; the 7 non-default accents in light and dark on
   a 12-brief sample (accents change color tokens only); "sidebar open and closed" read as every system unfolded vs the
   default on desktop, index open vs closed on phone (_nav.png beside _top.png in every config). Each brief is shot alone
   on the page with transitions frozen, the same way before and after, so a difference is the refactor's.
2. Themes layer: the theme-keyed rules (1063, almost all dark, from s136) set paint and shape only; one sets layout
   (#axtopfade display in dark) and becomes a token. The 90 "theme rules setting layout" in ui_lint are the
   html:is([data-theme],:not([data-theme])) specificity hack, which matches every theme and goes with the layers.
3. Minify and comments (D-20261105-6): the build minifies and strips comments from the page's style and script bundles and
   drops HTML comments outside them (18 section markers between briefs); brief markup is not minified, so content tools
   that match exact brief HTML keep working and briefs stay byte-identical.
4. Parity oracle: besides the pixel comparison the plan asks for, computed styles are compared element by element
   (tools/ui_styles.js), because a pixel diff cannot tell which rule moved; the review agent still reads only the
   pixel diff report.
